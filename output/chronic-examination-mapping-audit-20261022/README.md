**不能直接复用为现成 PHIS 对照。可以将标准名称作为受审映射的起点，但需要补齐机构级对照。** 当前对照表为空、标准医保码缺失、标准编号不是医嘱ID。不要把源码初始化 SQL 的新版对照当作现场已维护数据，也不要把27项的频次自动解释成本次患者必须开立。

| 推荐 | 现场候选例子 | 处理建议 |
| --- | --- | --- |
| 糖化血红蛋白 | 糖化血红蛋白测定；部分机构糖化血红蛋白组套 | 可优先评审同义词关系；核对组套明细、当前机构唯一ID和方法 |

| 心电图 | 常规心电图检查；常规心电图检查费 | 可优先评审常规项目；不含动态或扩展项目 |
| 血脂 | 血脂常规检查、血脂四项、六项、七项等 | 需核对具体明细，不自动选第一项或扩大组套 |
| 尿肾功能 | 尿微量白蛋白测定、尿肌酐测定、尿敏感肾功能等 | 原推荐可能包含组合，不能按名称猜测拆单 |
| 空腹/餐后二小时血糖 | 静脉、末梢、快速等多个目录 | 需确认标本、时间和检测方法，不能仅作字符串替换 |
| 颈动脉/腹部/下肢血管B超 | 通用超声收费项及各机构 PACS 部位 | 必须绑定正确部位、侧别、动静脉与执行科室，通用医保编码不足以唯一定位 |
| 胰岛素/C肽释放、葡萄糖耐量试验 | 单次及不同时间点检测 | 缺少已维护的整套对照，不自动用单次测定替代或拼出试验 |
| 四肢多普勒 | 四肢多普勒血流图 | 只作候选，确认是否同一检查及是否要求ABI/PWV，不混用血管超声 |

医保编码本身也不唯一：例如有效对照中，同一糖化血红蛋白编码覆盖普通、体检、生育等多个项目；同一血脂编码也对应多个不同条目。医保码只能生成候选，必须同时限定机构、用途、有效期、组套和部位。

后续如实施：服务端维护经现场确认的“推荐键/标准名 → 院内服务或组套/部位”对照；客户端仍只从本次实时可开立目录解析并校验。没有唯一命中则保留未匹配，医生确认后才回写，不持久化导出的开立目录。
